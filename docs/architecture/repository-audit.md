# Repository audit before migration

The original active API was `legacy/flask/admin_server.py` (Flask). It accepted upload and file activity alerts, assigned separate integer IDs within one table, persisted them through `legacy/flask/models.py` and the initial Alembic migration, and supported cooperating client decision polling. Analyst decisions, allowed uploads, CNIC highlighting, and escaped HTML previews were useful behavior. `legacy/windows/upload_monitor_agent.py` used Watchdog but sent every callback as an alert, scanned selected local text, and defaulted to personal folders. `legacy/windows/network_monitor_agent.py` and `legacy/windows/http_upload_blocker.py` described upload interception that psutil connection data could not substantiate. The latter's automatic request detector returned false.

The React app used one API client, and the Alerts page had local filtering and sorting. Dashboard contained integration placeholders. User activity and report Flask routes returned fixed sample numbers and named sample users. The Flask admin page and decision/preview routes did not consistently require administrative authentication. The frontend put an API key in browser environment variables. `start_dlp_system.bat` launched that legacy flow.

Preserved as migration reference: original Flask files, legacy tables and migration, original regression tests, Windows deployment/service utilities, and reusable styling. New Docker startup and React entry point use FastAPI and normalized tables. The old Flask code is not part of the active runtime. Legacy files remain available for the explicit `scripts/migration/migrate_legacy.py` import and historical comparison.

Remaining legacy concerns: those files still contain old mock reporting routes and insecure admin controls if someone starts Flask manually. The old Windows service/deployment utilities still target those scripts and are not a supported launch path for the new stack. `python scripts/migration/migrate_legacy.py` copies historical alerts into UUID keyed tables after schema migration, marking risk `UNKNOWN` and discarding raw previews. This command is idempotent; it is deliberately explicit so an operator can review imported data before presenting it.
